# NOS / NFL Pulse ERP — Repository Audit (27 Oct 2026)

Audited commit: `de830ac` on `main` (15 Oct 2026). Working tree was clean.

## Stack (verified from code)
- Web: Next.js + React + TypeScript (`apps/web`) — builds successfully.
- API: NestJS + Prisma + PostgreSQL (`apps/api`), Redis, docker-compose.
- 50 Prisma models; 111 API routes across 17 controllers.

## Critical finding: frontend was disconnected from the real backend
Commit `27c3074` (1 Oct 2026) removed the `/api/*` rewrite to NestJS. Since then
`apps/web/app/api/[...path]/route.ts` (in-memory mock, ~4,200 lines) answered every
request. Consequences:
- Confirmed orders / PO imports were stored in memory only and lost on restart.
- `/api/auth/login` accepted any email without a password and returned ADMIN.
- Many dashboard numbers come from bundled JSON demo files, not the database.

### Fix in this branch
`apps/web/lib/live-gateway.ts` + wrapper in the catch-all route:
- `NOS_API_MODE=live` forwards every route that NestJS implements to
  `API_INTERNAL_URL` (data persists in PostgreSQL, JWT + bcrypt login, server-side roles).
- Routes NestJS does not implement yet still use the mock and are tagged
  `x-nos-data-source: demo` so they can be found and migrated one by one.
- If the API is down in live mode, live routes return 502 — never silent demo data.
- Login page sends the password; a rejected live login no longer falls back to demo login.
- Default (`demo`) behaviour is unchanged.
- `scripts/verify-live-routes.ts` fails if the gateway route list drifts from the API.

## PO import

  and Test 8 asserts the rejection.
